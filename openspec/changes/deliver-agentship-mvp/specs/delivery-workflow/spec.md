## ADDED Requirements

### Requirement: DW-01 流程图校验及启动版本

The system SHALL enforce the following behavior. 系统必须支持具名有序阶段、阶段内具名节点、协调 Agent 和按需选取的多个子 Agent。常规前置依赖可指向同阶段或更早阶段。须拒绝直接和间接循环、常规依赖更晚阶段、末尾缺结束节点或条件路线缺失。跨阶段修复按 DW-05 控制。结束节点只作完成标记。运行使用启动时的流程及节点角色配置，后续保存供新运行使用。

追溯 UC-03、UC-05 / SD-B03、SD-F01、SD-I01。

#### Scenario: UAT-04 节点配置多个 Agent
- **WHEN** 选择两个可用角色并留一个未选，保存重开后启动，随后修改该流程节点的角色并启动第二次
- **THEN** 两次运行可查实际角色及各自版本；第一次继续使用原快照，第二次使用新配置，未选角色不派发。

来源 BR-09、BR-42、NFR-02 / FR-AG-01、FR-FLOW-05。任务 2.1、2.6、3.2、4.1。

#### Scenario: UAT-08 配置、选择并执行流程
- **WHEN** 配置两条具名流程，包含同阶段及跨阶段依赖；尝试配置常规依赖指向更晚阶段；保存有效版本后经搜索和下拉分别选择运行
- **THEN** 有效流程可重开核对阶段和依赖，指向更晚阶段的常规依赖保存失败；启动入口只选择；运行与看板反映所选配置，依赖节点须等上游完成。

来源 BR-08、BR-12、BR-15～BR-17 / FR-FLOW-01～03、FR-RUN-01、FR-RUN-03。任务 2.1、2.2、2.4、2.6、4.1。

#### Scenario: UAT-11 流程修改后的运行追溯
- **WHEN** 启动后修改阶段、前置关系和角色展示名，查看当前及历史运行，再启动新运行
- **THEN** 旧运行按原版本执行且保留原展示名，后续运行使用新版本。按权限读取历史结果时保留对应尝试与输入修订。

来源 BR-08、BR-09、BR-12、BR-16、BR-17、BR-42、NFR-02 / FR-FLOW-05、FR-AG-01、FR-RUN-03。任务 2.1、2.4、2.6、4.1。

#### Scenario: UAT-35 结束节点校验与运行完成
- **WHEN** 分别提交缺结束节点、结束节点不在末尾及末尾有效标记的流程，运行有效版本
- **THEN** 前两种拒绝保存；有效结束节点无 Agent，运行到达后才标为已完成。

来源 BR-12、BR-16、BR-38 / FR-FLOW-01、FR-FLOW-04。任务 2.1、2.4、2.6、4.1。

#### Scenario: UAT-42 循环依赖校验
- **WHEN** 分别提交 A→B→A、A→B→C→A 和解除循环后的配置
- **THEN** 循环配置拒绝保存并提示有循环依赖；解除后其他规则通过时可保存。

来源 BR-17、BR-44 / FR-FLOW-02。任务 2.1、2.6、4.1。

#### Scenario: UAT-44 条件分支必须配置两条路线
- **WHEN** 分别缺通过路线、缺需修复路线及补齐两路线提交
- **THEN** 前两者拒绝保存并指出缺失路线，后者在其他规则满足时可保存。

来源 BR-45 / FR-FLOW-06。任务 2.1、2.6、4.1。

### Requirement: DW-02 授权选择与启动条件

The system SHALL enforce the following behavior. 启动必须依序确定已选择或明确创建的需求、工作类型和已保存且有使用权限的流程。仅需求主负责人可启动；无仓库关联时类型固定为新功能，已关联时四类均手选且共享同一可用流程范围。描述仅在流程含需求阶段时可延后；其余情况须在任何 Git 准备前补齐。

追溯 UC-04 / SD-B02、SD-B03、SD-F01、SD-I01。

#### Scenario: UAT-10 启动信息缺失
- **WHEN** 分别缺确认需求、已有仓库工作类型、所选流程，并提交只输入搜索文字的表单或等价 API 请求
- **THEN** 分别显示缺项，系统不创建运行、不领取任务、不发起 Git 准备。

来源 BR-13～BR-15 / FR-REQ-03、FR-RUN-01。任务 2.2、2.6、4.1。

#### Scenario: UAT-30 需求发起权限
- **WHEN** 需求主负责人和副负责人分别发起同一有效需求，再以副负责人直调 API
- **THEN** 主负责人满足条件时可启动，副负责人请求被拒绝且不产生运行或 Git 副作用。

来源 BR-33、BR-34、NFR-01 / FR-REQ-04、FR-RUN-01。任务 1.3、2.2、2.6、4.1。

#### Scenario: UAT-51 启动后在需求阶段补齐描述
- **WHEN** 只填需求名称，选择含需求阶段的流程，执行到该阶段后由有权用户填描述
- **THEN** 允许初始启动，描述保存到需求及当前运行的适用内容，后续阶段可以引用。

来源 BR-01、BR-13 / FR-REQ-03、FR-RUN-01。任务 2.2、2.4、2.6、3.4、4.1。

#### Scenario: UAT-52 工作类型共用有权使用的流程
- **WHEN** 对已关联需求遍历四种工作类型，比较搜索和下拉可见结果，并直调选择受限流程
- **THEN** 四种均显示同一有权范围，受限流程在各入口及直接请求均不能选。

来源 BR-14、BR-15、NFR-01 / FR-RUN-01、NFR-PRD-01。任务 1.3、2.2、2.6、4.1。

#### Scenario: UAT-53 无需求阶段的流程启动前须填描述
- **WHEN** 以新需求和描述为空的已有需求选择无需求阶段的流程，先空描述提交后补齐
- **THEN** 空时提示并且无运行或外部动作，补齐且其余条件通过时可启动。

来源 BR-01、BR-13 / FR-REQ-03、FR-RUN-01。任务 2.2、2.6、4.1。

### Requirement: DW-03 Git 计划、关联及未知结果恢复

The system SHALL enforce the following behavior. 系统必须在启动校验通过后按需求仓库关联和工作类型准备 Git。新需求按用户填写的 GitHub 账号或组织创建公开仓库，从默认分支建 dev 再建 feature；已有仓的新功能、重构和常规修复从 dev 建对应工作分支，缺 dev 时先从该仓默认分支补建；紧急修复直接以该仓默认分支为基准。失败或结果不明时研发保持等待，按已确认恢复规则核对原请求及已完成步骤。

追溯 UC-04、UC-08 / SD-B04、SD-B05、SD-I04。

#### Scenario: UAT-02 Git 准备失败及恢复
- **WHEN** 在建仓和创建分支各步骤分别注入明确失败、远端成功但本地超时、无法确定结果
- **THEN** 看板给出待处理和原因，研发不启动；权限与恢复条件满足后，以原请求核对实际结果，复用已完成资源，禁止盲目重复外部操作。记录先前失败、核对证据和后续尝试。

来源 BR-02、BR-08、BR-11、NFR-03 / FR-RUN-02～03、FR-RUN-05。任务 2.3、2.6、4.1、4.2。

#### Scenario: UAT-09 已关联仓库的需求启动运行
- **WHEN** 以搜索和下拉选同一已关联需求，分别选择四类工作；紧急修复覆盖 main 和 master
- **THEN** 四类均使用原仓库；dev 分别派生 feature、refactor 和 fix，hotfix 从仓库实际默认分支派生；记录需求、类型、流程、仓库及分支。

来源 BR-02、BR-13～BR-16、NFR-02 / FR-REQ-03、FR-RUN-01～03。任务 2.2、2.3、2.6、4.1、4.2。

#### Scenario: UAT-16 已保存需求尚未关联仓库
- **WHEN** 选择已保存但无仓库需求，分别尝试三种非新功能类型，再填获准 GitHub 账号或组织，选新功能启动并重开需求
- **THEN** 前三种拒绝且没有副作用；成功后在所填 GitHub 命名空间创建公开仓库，并写入需求和运行关联，依次创建 dev 与 feature，再次打开按已关联需求处理。

来源 BR-02、BR-13～BR-16、NFR-02 / FR-REQ-03、FR-RUN-01～03。任务 2.2、2.3、2.6、4.1、4.2。

#### Scenario: UAT-17 已有仓库缺少 dev
- **WHEN** 对默认分支分别为 main 和 master 的无 dev 已有仓库，以新功能、重构及常规修复启动
- **THEN** 先从真实默认分支建 dev，再从 dev 创建对应 feature、refactor 或 fix；记录基准和工作分支后流程继续。

来源 BR-02、BR-16、NFR-02 / FR-RUN-02、FR-RUN-03。任务 2.3、2.6、4.1、4.2。

### Requirement: DW-04 阶段执行、产物门槛与结束条件

The system SHALL enforce the following behavior. 常规执行按阶段顺序推进，前一阶段所有应执行节点完成后，下一阶段的常规节点才可开始。只有同阶段、互不依赖、共同直接依赖已完成上游且各自其他前置条件满足的节点可并行；同阶段无共同上游的就绪节点按配置顺序执行。普通节点须在所选角色成功或由人工跳过失败项、且最终产物可引用后完成。协调 Agent 先汇总冲突产物，仍无法解决时等待人工。结束标记等待所有实际执行路线。

追溯 UC-05、UC-08 / SD-B03、SD-B04、SD-F02。

#### Scenario: UAT-37 普通节点完成后才启动依赖节点
- **WHEN** B 依赖 A，分别构造失败角色未处置、已跳过但无最终产物、产物冲突未解决、失败已处置且有最终产物
- **THEN** 前三种 B 等待。协调 Agent 先汇总冲突，仍无法解决时等待人工。最后一种 A 完成，B 在其余依赖满足时可开始。

来源 BR-16、BR-17、BR-40 / FR-FLOW-03、FR-AG-04。任务 2.4、2.6、3.2、4.1。

#### Scenario: UAT-38 阶段按配置顺序执行
- **WHEN** 对无显式依赖的后阶段常规节点，分别保持前阶段未完成和已完成，另触发跨阶段修复路线
- **THEN** 前阶段未完成时后阶段常规节点等待，完成后才评估自身依赖。跨阶段修复仅推进被选中的路线，完成后回到原检查。

来源 BR-16、BR-41 / FR-FLOW-03。任务 2.4、2.6、4.1。

#### Scenario: UAT-39 结束节点等待所有并行路线
- **WHEN** 两条实际并行路线通向同一结束节点，先只完成一条，再完成另一条
- **THEN** 一条完成时运行尚未完成；两条均完成后结束节点仅触发一次。

来源 BR-38、BR-41 / FR-FLOW-04。任务 2.4、2.6、4.1。

#### Scenario: UAT-40 同阶段节点未满足并行条件
- **WHEN** 同阶段 A 和 B 无共同上游、都可开始，分别配置 A 在前与 B 在前
- **THEN** 每次均按对应配置顺序逐个执行，前一节点完成前后一节点不启动。

来源 BR-41、BR-43 / FR-FLOW-03。任务 2.4、2.6、4.1。

#### Scenario: UAT-41 同一上游完成后并行
- **WHEN** A 与 B 同阶段互不依赖、共同直接依赖 C，且 A 另有前置 D；依序完成 C 与 D
- **THEN** C 未完成时两者等待；D 未完成时 A 等待；两者前置均满足且容量允许时执行可重叠。

来源 BR-17、BR-40、BR-43 / FR-FLOW-03、FR-AG-04。任务 2.4、2.6、4.1。

### Requirement: DW-05 检查路线、修复复查与后续发布规则

The system SHALL enforce the following behavior. 每次有效检查只选择「通过」或「需修复」对应路线。修复可跨阶段，每轮修复后在原运行重执行原检查节点。按检查节点独立计数，首轮计一。仍需修复且达上限时，受影响路线及其依赖等待，无关路线按原依赖与阶段门槛继续。当前聊天操作者可追加一轮或停止本次运行，缺有效结论时可触发重新检查。首期仅执行开发环境的测试与复查。未来启用正式发布时，须验证原检查针对修复后产物的通过结果和适用放行条件。

追溯 UC-07、UC-08 / SD-B03、SD-B04、SD-B05、SD-F02、SD-I04。

#### Scenario: UAT-03 测试失败或待放行
- **WHEN** 在开发环境让必测项失败，再使测试通过。后续正式发布场景另覆盖必测失败、适用确认未完成及两项均满足
- **THEN** 首期记录测试结论，失败时显示原因并阻止依赖测试通过的节点。后续正式发布时，适用条件满足前保持等待，未经授权的放行不得修改状态或调用外部服务。

来源 BR-06～BR-08 / FR-DEL-03～04、FR-RUN-03。首期任务 2.5、2.6、4.1 覆盖开发测试。正式发布分区后续实施。

#### Scenario: UAT-43 根据条件选择路线
- **WHEN** 同一流程分别给出通过与需修复的有效检查结论
- **THEN** 每次检查只启动结果对应的路线；另一路线保持等待或标为不适用，不能同时分派。

来源 BR-16、BR-45 / FR-FLOW-06。任务 2.5、2.6、4.1。

#### Scenario: UAT-45 修复后复查通过才允许发布
- **WHEN** 进入修复后分别令复查尚未开始、原节点复查仍需修复、原节点复查修复后产物通过
- **THEN** 首期核对复查关联原检查节点及新产物版本。复查未通过时，依赖通过结论的节点保持等待。正式发布分区留待后续验证，届时仍须通过适用的放行条件。

来源 BR-07、BR-46 / FR-FLOW-08、FR-DEL-04。首期任务 2.5、2.6、4.1 覆盖复查。正式发布分区后续实施。

#### Scenario: UAT-46 未达上限时自动再次修复
- **WHEN** 设置上限大于一，首轮修复后原检查仍需修复
- **THEN** 在同一次运行自动再修一轮，之后重执行原检查，计数按轮次增长。

来源 BR-46、BR-47 / FR-FLOW-08。任务 2.5、2.6、4.1。

#### Scenario: UAT-47 达到自动修复上限后等待人工
- **WHEN** 设置上限三，第三轮复查分别返回需修复和通过。达上限分区同时准备受影响路线的任务领取、外部写入授权和一条已满足前置条件的无关路线
- **THEN** 首轮计一，持续需修复时受影响路线及依赖等待且无自动第四轮。阻塞生效后，该路线不可取得新的任务或外部写入授权，无关路线按原条件继续。边界上通过时该路线可继续。

来源 BR-46、BR-47 / FR-FLOW-08。任务 2.5、2.6、4.1。

#### Scenario: UAT-48 达到上限后的人工操作
- **WHEN** 自动上限后尝试越权操作，再由当前标签页操作者执行一次追加修复和复查，仍失败后停止
- **THEN** 越权拒绝；授权只追加一轮，仍需修复时该路线再次待人工。停止整次运行后，所有路线均停止领取及新增外部写入。

来源 BR-46～BR-48 / FR-FLOW-09、FR-CHAT-04。任务 2.5、3.3、3.4、3.5、4.1。

#### Scenario: UAT-49 检查节点独立计算修复上限
- **WHEN** 串行配置检查 A 上限一、B 上限三，让 A 一轮复查通过后进入 B
- **THEN** B 从第 1 轮开始并可自动修至自身第 3 轮；A 的轮次与结果保留。

来源 BR-47 / FR-FLOW-08。任务 2.5、2.6、4.1。

#### Scenario: UAT-50 检查缺少有效结果时等待人工
- **WHEN** 注入缺结论和不可识别结论，由当前聊天操作者请求重新检查，分别返回有效和仍无效结果
- **THEN** 初始均待人工，原因可见且两路线未启动；原节点在同一运行重试，有效后才选路，再无效继续等待。

来源 BR-45、BR-49 / FR-FLOW-07、FR-CHAT-04。任务 2.5、3.3、3.4、3.5、4.1。

#### Scenario: EXT-03 发布结果不明后的恢复
- **WHEN** 发布供应商接受操作但响应丢失，原设备随后重连。另测拒绝、仍无法确定及已确认成功
- **THEN** 未知状态等待核对，以原发布引用查询并保留处理记录；未获核验前无成功结论或重复触发，已确认成功后关联目标、产物及回执。

来源 BR-07、BR-11、NFR-02、NFR-03 / FR-DEL-04、FR-RUN-05、NFR-PRD-02～03。该场景保留为后续正式发布验收。首期 Git 结果不明使用 UAT-02。

### Requirement: DW-06 交付可见性、产物及重试追溯

The system SHALL enforce the following behavior. 系统必须按权限展示一次运行的需求、项目、类型、仓库、基准及工作分支、流程版本、实际角色、节点状态和产物。产品定义须可供下游引用；前后端代码关联本次仓库及分支；测试结论和失败详情关联被测代码；后续正式发布启用时须留目标、产物及结果。可恢复失败须保留先前及后续尝试，记录获授权操作者和时间。模拟证据必须标明演练。可公开交付产物须归档到需求关联的 Git 仓库。账号资料、聊天原文和原始执行日志保留于平台，归档动作不得带入这些内容。

追溯 UC-04、UC-05、UC-08 / SD-B04、SD-B05、SD-F02、SD-I04。

#### Scenario: UAT-01 新需求从启动到开发交付
- **WHEN** 在开发环境填写获准的 GitHub 账号或组织，以仅有名称的新需求发起含需求补齐、产品、前后端、测试和结束的流程
- **THEN** 创建并关联仓库，由默认分支依次创建 dev 和 feature 后方启动研发，结束节点完成且看板可追溯全过程。核对需求仓库含可公开的产品定义、代码和测试交付物，并检查带有合成账号资料、聊天原文和原始日志的输入未被归档。使用模拟适配时必须标明演练，不能形成真实通过证据。

来源 BR-01～BR-06、BR-08、BR-13～BR-16 / FR-REQ-03、FR-RUN-01～03、FR-FLOW-03～04、FR-DEL-01～03。任务 2.2、2.3、2.4、2.5、2.6、3.1、3.2、4.2。

#### Scenario: UAT-06 节点失败和重试
- **WHEN** 令可重试节点失败，用获授权维护者发起恢复，再用未获权用户和重复请求尝试
- **THEN** 显示失败原因和可用动作；只产生允许的重试，原尝试及后续结果、操作者和时间均可查；越权无状态变更。

来源 BR-08、BR-11、NFR-02、NFR-03 / FR-RUN-03、FR-RUN-05、FR-AG-05。任务 2.4、2.6、3.4、4.1。
