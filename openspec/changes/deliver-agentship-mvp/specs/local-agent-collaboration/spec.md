## ADDED Requirements

### Requirement: LC-01 按需分工、执行顺序和局部重试

The system SHALL enforce the following behavior. 系统必须允许从可用角色中按需选择子 Agent，支持选三个或更多，仅向实际选择者分派任务，支持有序执行及默认并行。各角色可交换任务信息并双向对话。失败须显示具体角色、已确认原因或通用未知原因。失败角色等待当前聊天操作者选择重试或跳过。重试仅派发失败角色并沿用已成功角色结果。跳过保留原失败及操作者记录，节点仍须满足最终产物门槛。

追溯 UC-03、UC-05 / SD-B04、SD-F01、SD-F02、SD-I03。

#### Scenario: UAT-20 多个 Agent 参与同一节点
- **WHEN** 选两个角色并留一个未选，在运行中交换两角色任务信息，覆盖 Agent 主动提问、用户普通消息、`@Agent` 指定消息和无效目标
- **THEN** 只选中角色参与，转交抵达指定任务，普通消息送达协调 Agent，指定消息只送达目标 Agent，回复问题送达发问者。无效目标被拒绝，未选角色无执行记录。

来源 BR-09、BR-27 / FR-AG-01～03、FR-CHAT-01。任务 2.4、3.2、3.4、3.5、4.1。

#### Scenario: UAT-31 节点内 Agent 的执行先后
- **WHEN** 配置两个角色且有序运行，然后去掉顺序，以足够容量再执行
- **THEN** 有序版本按配置先后，默认版本可重叠；容量受限与三个以上角色另测 EXT-01。

来源 BR-09、BR-27、BR-35 / FR-AG-02、FR-AG-06。任务 2.1、3.2、3.5、4.1。

#### Scenario: UAT-36 仅重试失败的 Agent
- **WHEN** 一个角色成功另一个失败，覆盖已知和未知原因，由当前聊天操作者分别选择重试和跳过，再测非操作者直接提交
- **THEN** 界面显示失败角色、简明原因或暂时无法确认，等待人工处置。重试只为失败者增加尝试并沿用成功结果。跳过保留失败及处置记录，缺少最终产物时节点仍未完成。越权请求不改变结果。

来源 BR-11、BR-39、NFR-02 / FR-AG-05、FR-RUN-05。任务 2.4、3.2、3.4、3.5、4.1。

#### Scenario: EXT-01 三个以上子 Agent 与明确分派
- **WHEN** 从可用目录选择至少三个子 Agent，并留一个未选择。分别运行串行版、默认并行版和受限容量版
- **THEN** 只派发已选角色。串行版依配置顺序，并行版在容量允许时可重叠。受限容量按确认规则排队或给出明确原因；未选角色始终无执行记录。

来源 BR-09、BR-27、BR-35，PRD 补充验收 / FR-AG-01～02、FR-AG-06。任务 2.1、2.4、3.2、4.1。

### Requirement: LC-02 可寻址问答和确认后的需求变更

The system SHALL enforce the following behavior. 系统必须可定位发问角色和会话，问题持续待答至获授权回复或发起人取消。等待期间独立任务可继续。普通消息默认发给当前节点的协调 Agent，用户也可用 `@Agent` 指定该节点的 Agent。显式目标须属于当前节点及允许的会话范围。取消后发问角色依据已有信息续行。正式变更仅在正在执行的 BRD 节点内受理。运行发起人确认后，系统必须同时更新原需求与本次运行修订，供后续节点使用，并保留会话、变更和审计。尚未开始的节点采用新版本。已在执行的节点按原版本完成，结果标记为「基于旧版本」。已完成的节点默认保留，由发起人决定是否重跑受影响节点。

追溯 UC-06 / SD-B04、SD-F02、SD-I03。

#### Scenario: UAT-05 开发中与 Agent 对话
- **WHEN** 授权用户在运行内发送消息、收到回复并重新打开会话，在活动 BRD 节点提出变更，分别由获聊天授权的非发起人与发起人确认，确认时保持一个节点正在执行、另一个尚未开始，另测无 BRD 阶段或已离开该阶段
- **THEN** 会话可找回；待确认、越权或阶段不符时原需求和运行修订均不变。发起人确认后两处一起更新，在途节点按原版本完成并标记旧版本，未开始节点读取新版本。完成节点默认保留，另测发起人显式重跑受影响节点及审计记录。

来源 BR-01、BR-10、BR-51 / FR-CHAT-01、FR-CHAT-06、FR-REQ-03。任务 3.2、3.4、3.5、4.1。

#### Scenario: UAT-21 单个 Agent 等待用户回复
- **WHEN** 让 Agent A 提问、Agent B 执行独立任务，观察后从当前操作页提交答案
- **THEN** A 显示待答、回答框和按钮，B 可继续，答案只送 A 且 A 续行；重复提交不重复推进。

来源 BR-27、BR-28 / FR-AG-03、FR-CHAT-02。任务 3.2、3.4、3.5、4.1。

#### Scenario: UAT-33 待回复问题保留至回复或取消
- **WHEN** Agent 发问后关闭并重开页面，等待并重启平台测试进程，随后授权回复
- **THEN** 同一问题在关闭与平台重启后仍待答；回复使原问题结束等待，不重复建立问题或推进任务。

来源 BR-28、BR-37 / FR-CHAT-02～03、NFR-PRD-03。任务 1.1、3.4、3.5、4.1。

#### Scenario: UAT-34 发起人取消待回复问题
- **WHEN** 其他用户尝试取消，随后由持有标签页的发起人取消；另用并发回复与取消测试
- **THEN** 其他用户不能取消；发起人可取消且原角色用已有信息继续；回复与取消至多一方成功。

来源 BR-28、BR-37 / FR-CHAT-03。任务 3.2、3.4、3.5、4.1。

### Requirement: LC-03 聊天权限、单标签页和释放

The system SHALL enforce the following behavior. 发起人可添加或撤销运行的聊天用户，需求副负责人不得参与该需求已有运行的聊天。同一聊天只允许一个有权用户的一个标签页操作，已占用时有权竞争者看到当前使用者。撤权立即使原会话及操作权失效。收到活跃页显式离开或关闭通知时立即释放。通知未送达时，自检测断连起保留五分钟，期间原操作者可重连，届满后其他有权用户可取得操作权。

追溯 UC-06 / SD-B02、SD-B05、SD-F02、SD-I01。

#### Scenario: UAT-23 同一聊天页面单人使用
- **WHEN** 发起人授权第二名用户，双方同时进入。由竞争失败者直接调用消息、回复和敏感操作，再撤销受授权用户，另测被撤权页持有操作权时的访问
- **THEN** 一名用户的一个标签页取得操作权，另一方看到当前使用者且操作被拒绝。撤权后原页面和新请求均无法操作，旧会话不能继续占用。

来源 BR-10、BR-30、NFR-01 / FR-CHAT-01、FR-CHAT-04。任务 3.3、3.5、4.1。

#### Scenario: UAT-24 聊天页退出后立即释放
- **WHEN** 持有页分别显式导航离开和在网络正常时关闭，另一授权页随即进入
- **THEN** 占用即时释放并可由另一授权页取得；晚到的旧页释放请求不能清除新占用。

来源 BR-30 / FR-CHAT-04。任务 3.3、3.5、4.1。

#### Scenario: UAT-25 聊天页断网后保留占用
- **WHEN** 在受控时钟记录断网检测点，覆盖断网和关闭通知未送达两种情况，再验证五分钟前重连、竞争失败、刚满五分钟及超时进入
- **THEN** 检测后五分钟内保留原占用；期限届满后可重新取得；迟到的心跳不能恢复已失去的占用。

来源 BR-30、BR-31 / FR-CHAT-05。任务 3.3、3.5、4.1。

#### Scenario: UAT-26 同一用户打开多个聊天标签页
- **WHEN** 同一用户打开两个标签页，先关闭竞争页；另一次关闭持有页
- **THEN** 竞争页不能操作且关闭不会释放持有页；关闭持有页后另页可进入并操作。

来源 BR-30 / FR-CHAT-04。任务 3.3、3.5、4.1。

#### Scenario: UAT-32 需求副负责人无法参与运行聊天
- **WHEN** 聊天无人占用时，副负责人尝试进入，随后直调发送和回复接口
- **THEN** 均按角色权限拒绝，不返回消息或占用者详情，不修改会话。

来源 BR-36、NFR-01 / FR-CHAT-01、NFR-PRD-01。任务 1.3、3.3、3.5、4.1。

### Requirement: LC-04 原电脑执行和同次恢复

The system SHALL enforce the following behavior. 每次运行必须绑定经验证的发起电脑，所有协调及子 Agent 在该电脑执行，网页把消息发给本机对应 Codex 会话。发起电脑关机后平台保持可查并显示等待原电脑上线。原电脑和 CLI 恢复后，系统须继续原运行并保留已完成结果。原 Codex 会话可用时沿用，否则从最近保存的进度恢复。其他设备不得接管，旧尝试回报不得覆盖当前状态。

追溯 UC-06、UC-08 / SD-B05、SD-F02、SD-I02、SD-I03。

#### Scenario: UAT-22 网页聊天连接本机 Codex CLI
- **WHEN** 用两台已配对电脑，从 A 发起配置多个 Codex Agent 的运行，网页给不同角色发消息，B 尝试领取任务
- **THEN** 全部角色和各自 Codex 会话在 A，指定会话收到消息并回复；B 无法取得该运行任务。

来源 BR-10、BR-29 / FR-RUN-04、FR-CHAT-01。任务 3.1、3.2、3.5、4.2。

#### Scenario: UAT-27 发起电脑关机后恢复运行
- **WHEN** A 运行期间关机，从 B 查看；尝试从 B 接管；A 重启 CLI 后分别构造原会话可用和不可用，并提交旧尝试回报
- **THEN** B 能看到等待发起电脑上线但不能接管；A 沿用可用原会话或最近保存进度续跑，运行标识和已完成步骤保留，旧回报不能覆盖当前尝试。

来源 BR-29、BR-32、NFR-03 / FR-RUN-03～05、NFR-PRD-03。任务 1.1、3.1、3.2、3.5、4.1、4.2。

#### Scenario: EXT-02 旧设备租约与重复人工操作
- **WHEN** 原设备中断并重连同次运行，延迟提交旧租约回报；在同一问题上并发重复回复、回复与取消；晚到旧聊天页释放
- **THEN** 只有当前任务尝试可更新结果。回复或取消至多一次推进，原结果、任务和运行身份可追溯。旧页事件不能影响已接管的新占用。

来源 BR-28、BR-30～BR-32、BR-37，PRD 补充验收 / FR-RUN-04、FR-CHAT-02～05、NFR-PRD-03。任务 3.1、3.3、3.4、4.1。
