## ADDED Requirements

### Requirement: WA-01 注册、登录与资料保护

The system SHALL enforce the following behavior. 注册公开开放，接收姓名、用户名、手机号、邮箱及两次密码输入。系统须验证手机号和邮箱。用户名允许英文字母、数字、下划线和短横线，最多 100 字符，唯一性判定忽略大小写。两次密码须一致。已激活账号可用邮箱或用户名搭配密码登录。业务访问要求登录，本人登录后才可读取自己的邮箱和手机号，首期管理员查阅及停用后台留待后续，密码和确认密码不得写入业务、运行或变更记录。密码为 15～128 个字符，允许空格和符号，两次输入须完全一致。注册后账号待验证，邮箱和手机号都验证成功才激活并允许登录。同一个邮箱、同一个手机号各只能绑定一个账号。邮箱不区分大小写，手机号统一带国家区号判重。注册受理后待验证状态保留 24 小时。未完成双渠道验证而到期时，原验证码失效，释放用户名、邮箱和手机号，允许重新注册。首批开发和验收使用本地模拟邮件和短信，真实发送待供应商确定后接入。

追溯 UC-01 / SD-B02、SD-F01、SD-I01。

#### Scenario: UAT-12 注册及校验
- **WHEN** 用含字母、数字、下划线和短横线的用户名注册，覆盖 100 与 101 字符、仅大小写不同的重复名、并发重复、密码 14／15／128／129 字符、空格和符号、密码确认不一致，规范化后的联系方式重复、任一验证失败，以及 24 小时到期和重注册
- **THEN** 100 字符通过长度检查，101 字符被拒绝。仅大小写不同及并发重名至多创建一个有效账号。密码不一致不会创建账号。仅一项验证成功仍不能登录，第二项成功后原子激活。失败保持未验证。重复联系方式最多绑定一个账号。过期后可使用相同标识重新注册，旧验证码仍拒绝。本地模拟须覆盖两个渠道。

来源 BR-18、BR-19 / FR-ACC-01。任务 1.2、1.4、4.1。

#### Scenario: UAT-13 登录与页面访问
- **WHEN** 未登录直接打开业务页和 API；分别以同一账号的邮箱、用户名和正确密码登录，再用错误密码登录
- **THEN** 登录及注册可访问，未登录业务访问受保护；两种合法凭据进入业务页，错误凭据及未激活账号不获得会话。

来源 BR-20、BR-21 / FR-ACC-02。任务 1.2、1.4、4.1。

#### Scenario: UAT-15 账号资料保护
- **WHEN** 以无权用户检查账号字段、页面与 API，检查运行、配置变更和审计输出
- **THEN** 当前账号可读取自己的联系方式。其他用户及成员列表不返回他人手机号或邮箱，任何业务记录不含密码和确认密码。

来源 NFR-04 / FR-ACC-01、NFR-PRD-04。任务 1.1、1.2、1.4、4.1。

### Requirement: WA-02 三类配置负责人管理

The system SHALL enforce the following behavior. 创建 Agent、流程或需求配置时，系统必须设创建者为主负责人。仅主负责人可增删副负责人（可移除最后一位）或转交给其他注册用户。新增副负责人和转交通过注册用户名选人。副负责人可查看和编辑获授权对象。流程副负责人可在自己有权启动的运行中选用该流程，Agent 副负责人可在自己有权编辑的流程中选用该 Agent。移除和转交须立即生效，候选、保存和启动按当时权限判断。流程和 Agent 的使用权来自当前主、副负责人身份，并须满足对应启动或编辑权限。单独向非负责人授予使用权留待后续。

追溯 UC-02 / SD-B02、SD-F01、SD-I01。

#### Scenario: UAT-14 三类配置的负责人管理
- **WHEN** 对需求、流程和 Agent 配置分别创建、增删副负责人；从启动入口新建需求；副负责人编辑已分配和未分配配置并尝试管理名单
- **THEN** 各创建者为主负责人；已分配内容可编辑，其余访问和副负责人管理名单均拒绝；删除最后一位后主负责人仍在。另验流程和 Agent 副负责人的相应使用权，以及撤权后的旧选项和直调提交被拒绝。

来源 BR-22～BR-24、NFR-01 / FR-OWN-01、FR-REQ-01。任务 1.3、1.4、2.2、4.1。

#### Scenario: UAT-18 移除副负责人后尝试保存
- **WHEN** 三类配置各打开副负责人编辑页，主负责人移除其权限且提交后，副负责人尝试从旧页和 API 保存
- **THEN** 拒绝并提示已被移除，配置保留先前已保存版本；并发结果符合权限撤销与保存提交顺序。

来源 BR-23～BR-25、NFR-01 / FR-OWN-02。任务 1.3、1.4、4.1。

#### Scenario: UAT-19 主负责人转交
- **WHEN** 对三类配置按用户名转交给此前未担任副负责人的注册用户。接任者和原负责人随后尝试增删副负责人，再由原负责人重放原转交请求并刷新详情
- **THEN** 转交原子生效且无需接任者再操作。新主负责人可管理名单。原负责人失去原角色权限，重放不重复转交或返回配置详情，随后读取按当前权限裁决。

来源 BR-23、BR-26 / FR-OWN-03。任务 1.3、1.4、4.1。

### Requirement: WA-03 需求可见性、名称唯一及敏感操作

The system SHALL enforce the following behavior. 系统必须按当前角色限制需求、流程、项目、Agent 配置及敏感操作。需求默认仅创建者可见，授权副负责人可查看、编辑，原主负责人转交退出后不得再访问。需求名称须全平台唯一；仅有权选择已有需求者可获选择提示，其他用户只见通用错误。

追溯 UC-02、UC-04 / SD-B02、SD-F01、SD-I01。

#### Scenario: UAT-07 权限隔离
- **WHEN** 无权限用户经列表、搜索、下拉、详情、直调 API 及敏感操作尝试访问受限需求、项目、流程、Agent 或发起受限外部动作
- **THEN** 入口均按相同授权策略拒绝，响应不泄漏对象详情，不修改配置或触发外部动作。

来源 NFR-01 / NFR-PRD-01、FR-REQ-01、FR-RUN-01。任务 1.3、1.4、2.2、2.5、4.1。

#### Scenario: UAT-28 需求默认仅创建者可见
- **WHEN** A 创建需求，B 检查列表、启动搜索和下拉及直接链接；A 将 B 加为副负责人后重试访问并编辑
- **THEN** 未授权时各入口不暴露需求；授权后可见可编辑，副负责人发起权限另测。

来源 BR-01、BR-23、BR-24、BR-33、NFR-01 / FR-REQ-01、FR-OWN-01。任务 1.3、1.4、2.2、4.1。

#### Scenario: UAT-29 需求转交后原创建者失去查看权限
- **WHEN** A 将需求主负责人转交给 B，两人重新访问列表、搜索、下拉及详情链接
- **THEN** B 立即有权访问；A 同时失去原角色授予的查看权。

来源 BR-26、BR-33、NFR-01 / FR-REQ-01、FR-OWN-03。任务 1.3、1.4、2.2、4.1。

#### Scenario: UAT-54 已有同名需求时选择原需求
- **WHEN** 主负责人在启动与配置入口重复创建同名需求，另一用户跨项目同名提交；两用户并发首次提交另一名称
- **THEN** 有权用户收到选择已有需求提示，使用原记录；无权用户只见名称不可用；并发同名至多新增一条且不泄漏原需求。

来源 BR-13、BR-50、NFR-01 / FR-REQ-02～03、NFR-PRD-01。任务 1.3、1.4、2.2、4.1。
