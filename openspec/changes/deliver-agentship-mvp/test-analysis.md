## 2. 变更影响

### 本批启动与设备前置验收

用户要求继续下一批，范围为 2.2，及 2.6 的启动/只读运行详情、3.1 的配对和证明、3.5 的设备页面分区。后端启动、设备边界与前端交互分别由单一 TDD 实施代理负责，主代理负责契约、整合和真实 Chrome 回归。已有 TA 的 UAT-01、07～11、14、16～17、22、27～30、51～54 只验收下列分区，不把它们整体标为完成。

| 分区 | 正向与反向验收 | 类型与责任 |
|---|---|---|
| 选择和启动 | 搜索及下拉确认已有需求，明确新建；重复名称选择原记录；新需求固定新功能，已有仓库四类手选；流程只能选有权保存版本；纯输入文字不产生运行 | 前端 TDD、Chrome 整合 |
| 启动闸门 | 非需求主负责人拒绝；流程及全部固定 Agent 当前使用权重检；过期需求或流程版本拒绝；无需求节点且空描述拒绝，有需求节点允许延后；撤权与失败无运行副作用 | Java HTTP / PostgreSQL TDD |
| Git 计划 | 未关联仓库只允许 feature 且需命名空间；已关联仓库沿用原关联，四类分别给出 dev 或真实默认分支策略；不伪造 main/master、仓库或提交成功证据 | Java HTTP、Chrome 展示 |
| 配对与同机证明 | 限时一次配对、公钥签名、账户/会话/来源绑定；过期、重用、错误签名、错误设备或来源拒绝；证明消费与运行创建同事务 | 设备 Java/HTTP TDD |
| 去重与快照 | 同键同输入返回原运行，不再消费挑战；冲突输入拒绝；并发同键最多一条；保存的需求修订、流程及 Agent 版本不被后续编辑覆盖 | Java PostgreSQL、重启验收 |
| 本机程序与界面 | Java 本机进程配对、精确 Origin、回环证明、心跳在线、停止后离线、重新启动同一设备；Chrome 完成证明与启动、刷新详情和窄屏；看板不显示未执行的成功状态 | 设备集成、主代理 Chrome |

完整运行派发、跨设备实际执行、Codex/GitHub 及聊天不在本批通过结论内。命名、时效和协议常量等实现默认在设计和证据中明确记录，不转写为用户新确认。

执行结果：本批运行接口 7 组、设备 4 组、真实 Java companion 与 Chrome 3 组通过；既有账号/权限/浏览器 6 组、流程图 3 组回归通过。任务 2.2 完成，其余任务只记录对应分区，详见 [验证证据](evidence.md#2026-11-09-启动运行与本机设备)。

### 本批流程配置验收

用户在 2026-11-09 授权继续实现阶段、节点、依赖及多个 Agent 配置，并重绘 Logo。对应任务 2.1 和 2.6 的流程编辑器分区。本批依据现有 DW-01、LC-01、WA-02、SD-B03、SD-F01 与 draft.9 契约实施。阶段/节点保存与图校验具有稳定自动化预期，后端和前端分别采用测试先失败、再实现通过的方式，实际证据进入 `evidence.md`。

| 本批验证分区 | 对应用例 | 自动化预期 | 执行责任 |
|---|---|---|---|
| 有序阶段与节点 | UAT-08、35 | 名称、稳定 ID、顺序保存重开一致；空阶段、缺失或错位结束点拒绝；结束点不接受 Agent | Java 流程实现与 HTTP/PostgreSQL 验证 |
| 依赖完整性 | UAT-08、42 | 同阶段和更早阶段依赖有效；自引用、失效引用、循环、晚阶段及结束点前置依赖拒绝，失败事务无新增版本 | Java 流程实现与 HTTP/PostgreSQL 验证 |
| 角色选择与顺序 | UAT-04、31、EXT-01 | 一名协调者与至少三名选定子 Agent 完整保存，未选择角色不入配置；并行默认值与串行列表顺序保留 | Java 流程实现、React 编辑器及 Chrome 验证 |
| 检查与修复路线 | UAT-44、46～47 的配置分区 | 两个有效不同入口、路线归属与各检查上限保存；缺路线、互斥依赖及无法完成的路线拒绝；跨阶段修复采用条件路线引用 | Java 流程实现与 HTTP/PostgreSQL 验证 |
| 配置版本与权限 | UAT-07、11、18 | 旧图与角色版本不可变；旧提交版本拒绝；Agent 撤权后保存拒绝；同键重放不新增版本 | Java 流程实现与真实数据库验证 |
| 可视编辑与回归 | UAT-04、08、14、35、42、44 | 页面完成新增、删除、排序、依赖与角色选择、保存和重开；校验错误保留草稿；桌面及手机可操作；账号和负责人管理回归通过 | React 编辑器实现与独立 Chrome 验证 |

本批默认允许仅配置协调 Agent，`agentIds` 可为空。这是按现有可选字段与按需选择原则采用的实现默认，SA-D05 的产品复核继续保留。配置版本封存验证服务于后续启动绑定，真实派发、阶段调度、修复执行和运行快照验收随 2.2～2.5、3.2 继续。

平台迁至 Java Spring Boot 与 PostgreSQL，前端改为 React + TypeScript 静态应用，Java worker 在每次运行的发起电脑执行。影响范围包括同源 API、身份授权、流程快照、节点输入修订、调度、消息、租约、GitHub/Codex 适配和审计。首期以开发环境验证，迁移及回退使用隔离数据库。
