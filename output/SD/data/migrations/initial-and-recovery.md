# AgentShip 数据迁移与恢复设计 v0.4

状态为 Proposed。[初始物理 DDL](../agentship-postgresql-ddl.sql)及[隔离断言](../agentship-postgresql-assertions.sql)用于设计验证。旧原型数据是否纳入及导入授权待定。

| 阶段 | 变更及准入 |
|---|---|
| M1 盘点 | 确认权威数据、业务归属、保留与删除要求。若存在获准导入的原型数据，定义旧键到稳定 ID 和版本的映射。 |
| M2 隔离验证 | 在可丢弃数据库核对结构、权限、预备语句和断言。迁移账户、版本号及应用账户分别批准。 |
| M3 兼容扩展 | 先部署可兼容新增结构，核对应用/API/Worker 版本矩阵，记录锁、时限、WAL 空间和维护窗口。 |
| M4 条件回填 | 数据获批后再设计分批、可暂停、可重跑的导入。检查角色、唯一键、版本封存和引用。演练证据不转换为真实结果，未知外部动作需核对。 |
| M5 验收切换 | 核对数量、权限、快照、状态、证据和负例，验证备份恢复后分批切换兼容客户端。 |
| M6 收口 | 观察兼容窗口与异常指标，旧消费者退出后再评估清理。删除、脱敏、归档须有相应授权。 |

回退优先使用兼容应用版本和可确认的数据库状态。不可逆变化经批准采用前滚修复或从已验证备份恢复。恢复前冻结外部写入并核对真实仓库和发布结果。RPO、RTO、备份频率、留存和恢复责任待批准。
