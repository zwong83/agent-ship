# AgentShip 事务与并发矩阵 v0.5

[数据设计](../SD-AgentShip-data.md) · [功能读写契约](dml-catalog.md) · [参数化 DML](agentship-postgresql-dml.sql) · [数据库断言](agentship-postgresql-assertions.sql)。

拟议隔离级别为 Read Committed。预期写入返回零行时拒绝并回滚命令。允许为空的授权查询、候选和领取请求可正常返回空。

| 事务 | 边界与顺序 | 重复和冲突 | 恢复与验证 |
|---|---|---|---|
| TX-AUTH | 按稳定顺序锁并释放冲突的过期待验证记录，然后按三个唯一键注册。验证锁定账号后按数据库时间检查 24 小时边界，第二项通过时同事务激活。仅对激活账号查登录键，应用验证口令并签发会话 | 账号判重、会话到期和撤销返回安全结果 | 不授予错误凭据业务权限，检查资料保护。UAT-12、13、15 |
| TX-CFG | 锁对象，再核对当前角色、预期版本及目标；新增受唯一键保护 | 编辑、撤权和转交按同对象行串行，旧页不得覆盖 | 版本、权限或同名冲突整条回滚。UAT-04、08、11、14、18、19、42、44、54 |
| TX-READ | 当前授权下读单条或有界页 | 版本和游标防止旧投影覆盖新状态 | 游标过期重取授权快照，无权不给数据。UAT-07、11、27～29 |
| TX-RUN | 账号和收据 → 需求／流程有序锁 → 同机挑战 → 运行、修订与任务 | 同一作用域、键和摘要复用原结果，不同摘要冲突 | 挑战只消费一次，校验失败无运行或 Git 任务。UAT-01、09、10、16、30、51～53、EXT-02 |
| TX-DESC | 提交权限及收据 → 需求 → 运行 → 当前需求节点。仅在有效补录窗口更新 | 同时核对预期需求版本、运行修订和请求键；一次更新目标需求和本次运行输入 | 提交成功才开放相应下游。旧请求、窗口关闭或无权时拒绝。其他运行不反写。UAT-51 |
| TX-TASK | 发现候选运行 → 跳过已锁运行 → 新快照复核路线 → 锁候选尝试 | 当前设备、尝试、世代的下一序号才受理。旧世代、缺号拒绝 | 原机恢复同次运行和已确认产物。首次成功领取固定节点和角色输入修订。终态停全局派发，修复上限只阻断受影响节点。UAT-22、27、31、37～41、EXT-01、02 |
| TX-CHAT | 配置 → 运行 → 占用 → 目标问题或失败角色 | 发起人授予或撤销聊天来宾权限，撤销同时清理占用。普通消息与定向收件箱同事务。答复和取消争用同一终结，失败尝试可处置为跳过 | 旧页拒绝。答复、投递及审计同事务，设备离线时仍保存。UAT-05、21、23～26、32～36、EXT-02 |
| TX-CHANGE | 收据 → 需求 → 运行 → 当前聊天操作权 → BRD 节点和提案 | 校验发起人身份、活动节点、原需求版本和运行修订，原需求与运行修订同事务更新 | 未确认、旧页、并发版本冲突和阶段关闭时两处保持原值。节点首次成功领取与确认按运行锁串行。已领取节点沿用原修订，排队但未首次领取的节点采用当时最新修订。按需重跑由发起人触发。UAT-05 |
| TX-CHECK | 运行 → 当前检查／波次 → 修复轮次和操作权 | 每个检查每波至多一轮，独立自动计数 | 无结论等原检查，修复上限按授权再修一轮或停止。UAT-03、43～50 |
| TX-EXT | 配置和运行 → 原外部操作；供应商调用前后分别短事务记意图和证据 | 稳定操作键、有效租约、路线仍开放、目标及工件约束 | 结果未知先核对。停止后的独立只读核对资格待定。UAT-01～03、09、17、45、EXT-03 |

多对象操作按稳定 ID 顺序加锁，避免锁内网络或进程调用。死锁和瞬态冲突重试整个可重放数据库事务，次数与退避由运维决定。外部副作用按原操作和证据恢复。隔离合成两连接争抢已验证，生产规模执行计划及恢复实验仍待实施。历史证据见 [OpenSpec evidence](../../../openspec/changes/deliver-agentship-mvp/evidence.md)。

SD-Q01 的受影响集合从当前运行的达上限原检查、活动修复路线入口和成员出发，沿封存版本的硬依赖递归。调度仍遵循阶段门槛及分支激活。上限状态写入、任务领取和外部写入授权共同使用运行锁。领取遇到已锁运行跳过，获得锁后再读取路线。外部授权先在独立语句取得配置和运行锁，再读取路线并记录许可。此顺序要求 Read Committed。已派发操作按原操作键只读核对，超出既有授权的终止后核对留待 SA-D08。

使用现有 PostgreSQL 工具和 psycopg 验证。脚本创建项目内隔离数据目录并停止新起的服务，数据库只接受回环连接。

```sh
python3 output/SD/data/verify-postgresql-design.py \
  --pg-bin .agentship/verification/tools/pg17/bin \
  --psycopg-path .agentship/verification/pg-python
```

脚本先运行合成断言，再让连接 A 在未提交的运行锁内写入修复上限。连接 B 的领取返回空，外部授权在运行锁等待。A 提交后，B 拒绝受阻路线的写入授权。随后验证无关路线仍能领取并取得写入授权。
