## 3. Test data and ownership conventions

`Model` = dashboard_model, governing unit-testing-standard through its active TDD workflow. `UI-code` = assigned dashboard UI implementation/TDD owner, governing unit/UI standards. `Browser` = root acting as local UI verification owner using CUA and ui-testing-standard. `Regression` = root, collecting current-snapshot results. No case has competing execution owners; reuse a lower-level result only when its oracle and snapshot match.

All cases are planned. P0 is required behavior; P1 is required visual/responsive/regression evidence for this increment. U = deterministic automated unit/component check; B = real local browser check; R = existing suite rerun. Unit fixtures use synthetic requirements, runs, nodes, waves, tasks, permissions and connectivity. Browser fixtures use a separate test account and recorded local API/PostgreSQL data; no production identity or secret is captured in evidence.
